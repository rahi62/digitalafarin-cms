# برنامه تکمیل امکانات DigitalAfarin CMS
تاریخ مبنا: ۱۳ اکتبر ۲۰۲۶
مبنای توسعه: شاخه `feat/cms-route-registry-validation` و PR #54. هیچ Merge یا Deploy بدون تأیید انجام نمی‌شود.

## اصل پذیرش
نصب موفق پکیج *یک پیش‌نیاز برآورده‌شده* است، نه ملاک تکمیل محصول. پیش از آزمون پذیرش واقعی، کاربر مدیر باید بتواند همه جریان‌های مدیریت محتوا را از رابط گرافیکی و با کنترل دسترسی صحیح انجام دهد. CI خودکار در طول توسعه برای جلوگیری از رگرسیون ادامه دارد؛ آزمون نهایی میزبان بعد از بسته‌شدن فهرست امکانات است.

## قابلیت‌های موجود یا پیاده‌سازی‌شده روی شاخه توسعه

- [x] Django/DRF + Next.js SDK + CLI، نصب پکیج و Admin داخل برنامه میزبان (اصل نصب را کاربر تأیید کرده).
- [x] مدل چندسایته، سازمان، عضویت، Roleهای مالک/مدیر/سئو/ویراستار/نویسنده/بیننده (Backend).
- [x] صفحه مدیریت سایت‌ها و سازمان‌ها در Admin (شاخه توسعه؛ منتشرنشده).
- [x] مدیریت عضویت کاربران **دارای حساب Django** با نام کاربری و حفاظت از نقش مالک (شاخه توسعه؛ منتشرنشده).
- [x] مدیریت Content Type، تعریف Custom Field و تنظیم مسیرها (موجود).
- [x] ساخت، ویرایش، مدیریت وضعیت انتشار و پیش‌نمایش محتوا (موجود؛ UX در حال بهبود).
- [x] Rich Text + بلوک‌های پیشرفته، رسانه، taxonomy، منو، سئو/اسکیما/لینک‌های داخلی (موجود).
- [x] مدیریت بلوک‌های آماده و درج آن‌ها به‌صورت کپی مستقل در ویرایشگر پیشرفته (شاخه توسعه).
- [x] داشبورد عملیاتی، فیلتر و صفحه‌بندی محتوا، ناوبری بهینه‌تر موبایل، پرش بین بخش‌های ویرایش (شاخه توسعه).
- [x] CLI Route Discovery/Route Mapping/Validation و Route Explorer مبتنی بر snapshot احرازشده (شاخه توسعه).
- [x] محدوده‌سازی CSS ادمین Embedded با `@scope` برای حفاظت از UI میزبان (شاخه توسعه).

## امکانات باقی‌مانده تا تکمیل محصول

### P0 — الزامی پیش از آزمون پذیرش
- [ ] کامل‌کردن onboarding مدیریت سایت، وضعیت اتصال API و راهنمای پیکربندی.
- [ ] تکمیل Route Explorer از حالت snapshot/کپی دستور به یک جریان بازبینی یکپارچه؛ بررسی عملی مالکیت مسیر، Content Type، Loading/404، middleware و Next rewrites بدون بازنویسی خودکار صفحات.
- [ ] بهبود فرم‌های مدیریت Content Type و Custom Field: اعتبارسنجی **نوع مقدار** در Backend، پیام خطای قابل فهم، پیش‌نمایش و کنترل سازگاری تغییر schema.
- [ ] بهبود ذخیره خودکار/ویرایش همزمان/Revision: جلوگیری از ریزنسخه‌های بی‌مصرف و حفظ تاریخچه معنی‌دار، مدیریت race و خطای شبکه.
- [ ] تکمیل امنیت Admin: Refresh و انقضای نشست، راهبرد امن‌تر نگهداری JWT، کنترل نقش برای عملیات حساس و عدم نمایش اطلاعات بین Tenantها.
- [ ] مدیریت واقعی کاربران: **ایجاد حساب/دعوت ایمن** علاوه بر اتصال حساب‌های موجود، چرخه پذیرش دعوت و بازیابی دسترسی با رعایت نقش‌ها.
- [ ] نهایی‌سازی UX تمام فرم‌ها: موبایل، RTL، Keyboard/Accessibility، حالت خطا و خالی، Save/Cancel، بازخورد موفقیت، صفحات طولانی.
- [ ] بازبینی همه جریان‌های Media، Menus، Taxonomies و SEO/Schema از نظر عملیات کامل CRUD و بازخورد واقعی خطاها.

### P1 — امکانات عملیاتی تکمیلی
- [ ] عملیات گروهی محتوا، جستجوی پیشرفته و مدیریت پیش‌نویس‌ها.
- [ ] Import/Export امن محتوا همراه با Media/Redirect Mapping و گزارش تعارض (با پشتیبان‌گیری و بدون حذف دائمی خودکار).
- [ ] مدیریت نسخه‌های بلوک آماده و تعیین صریح «کپی مستقل» در برابر «بلوک سراسریِ همگام‌شونده»؛ سازگاری با public renderer.
- [ ] نظارت و گزارش خطاهای انتشار، وضعیت صف انتشار زمان‌بندی‌شده و Audit Log عملیاتی.
- [ ] UX پیشرفته ویرایش در مقیاس محتوا: navigation، میان‌برها، SEO checklist و تجربه سریع موبایل.

## معیار پایان فاز توسعه
۱. هیچ دکمه یا جریان اصلی صرفاً نمایشی نباشد؛ عملیات API، دسترسی و پیام خطا شفاف باشد.
۲. قابلیت‌ها برای Site/Role واقعی تعریف و UI متناظر داشته باشند.
۳. هیچ فایل Route، Layout، Middleware یا CSS موجود میزبان به‌صورت خودکار و مخرب تغییر نکند.
۴. CI برای جلوگیری از Regression سبز باشد.
۵. تمام موارد P0 بسته و P1 بر اساس دامنه نسخه تصمیم‌گیری شوند.
۶. **پس از این مرحله** آزمون پذیرش یکپارچه در پروژه نمونه واقعی آغاز شود.

> وضعیت‌های [x] در این سند به معنی وجود پیاده‌سازی در شاخه توسعه هستند، نه تأیید UX نهایی یا انتشار نسخه جدید.
